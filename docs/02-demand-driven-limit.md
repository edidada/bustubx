# LIMIT 按需消费与提前终止

## 问题

现有 PhysicalLimit 在检查已输出行数之前调用子节点 next，因此 LIMIT 1 实际会
读取两行，LIMIT 0 也会读取一行。如果第二行求值失败，已经满足 LIMIT 的查询
仍返回错误。并行投影虽然按行延迟普通错误，仍会被这一额外读取触发。
现有 `offset + limit` 还可能发生 usize 溢出。

## 设计

将单个原子游标替换成 Mutex 保护的三个字段：待跳过行数、剩余输出配额
（None 表示无限制）和结束标记。构造与 init 均设置为原始 offset/limit。
每次 next 先检查结束或配额为零，满足则直接返回 None；随后按需消费 offset，
遇到子节点 EOF 立即记住结束状态；返回一行时配额减一。只使用减法，避免
offset 与 limit 相加和不断增加计数导致的溢出。子节点错误照常返回。

LIMIT 不再消费配额以外的行。并行投影自身仍可能预取一批只读输入，但未消费
行的普通 Result 错误不影响 LIMIT；线程启动失败和 panic 的处理沿用第一阶段。
不修改逻辑优化规则、SQL 语法及输出 schema。

## 验证与交付

先新增回归测试，在旧实现上确认 LIMIT 0、LIMIT 1 后的错误行，以及超大配额
失败。测试覆盖串行/并行投影、OFFSET、无上限、提前 EOF、错误正常传播、
反复 next EOF 和 init 后重用。随后修改执行器，运行工作区全部测试、fmt 和
diff 检查。通过后设计、实现、测试及 README 独立 commit、push。

## 验证结果

修改执行器前：3 个定向测试中 2 个失败，分别复现额外读取导致错误及加法溢出。
修改后：`cargo test --workspace` 全部通过，含 48 个库单测、2 个并行 SQL
集成测试，以及 1/4 线程的完整 SQL logic test 套件。
