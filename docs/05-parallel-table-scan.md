# 并行表扫描：页批次与并行记录解码

## 范围与依赖

依赖 04 的多页写入修复。顺序表扫描在 workers > 1 时采用页批次执行，默认
workers=1 保留 TableIterator 路径。已有索引扫描仍串行；写语句整棵计划串行。
这不是并发磁盘 I/O：当前 BufferPool 的 miss/pin/eviction 不是原子操作，
不能让多个线程直接 fetch_page。调用线程依次取得页副本并立即释放 PageRef，
工作线程只负责独立页内全部记录的 TupleCodec 解码。

## 状态和执行

每批最多 16 个 TablePage 副本（每页 4096 字节，加页目录），用已有 ordered_map
按页并行解码。结果按页链顺序及 slot 顺序合并到队列，每次 next 消费一条。
读取 next_page_id 后继续下一页，不假定 page_id 连续；空页继续跳过。
单页输入无需启动额外线程。每批输出最多为这 16 页容纳的记录数。
状态保存 heap、next_page_id、已访问页号集合和待输出队列；集合 O(页数) 用于
检测错误页链环，遇到重复页返回 Storage 错误，避免无限循环及无限重复输出。
init 重建全部状态，保证嵌套循环连接重复扫描正确。

## 错误与兼容性

获取页面失败放在已获得页面记录之后；单页记录解码错误按 slot 顺序保存并停止
该页解码，正常 Result 错误仍在消费时返回。线程故障按公共工具的规则报告。
LIMIT 提前终止可以释放剩余批次；无遗留工作线程。保持原扫描的 schema 和
已删除记录处理语义（本项目事务可见性尚未实现），不在此阶段伪称具备 MVCC。
不改变磁盘格式，不增加第三方依赖。

## 验证

5000 行跨页表覆盖多个 16 页批次、尾批、完整顺序、WHERE/ORDER BY/LIMIT 和
flush/reopen。串行与 2/4 线程逐行比较。算子验证空页、非连续页号、页链环、
重复 init、重复 EOF 和 pin 释放。计划测试验证 ParallelSeqScan 被选择。
全工作区测试、格式和差异检查通过后独立提交并推送。
