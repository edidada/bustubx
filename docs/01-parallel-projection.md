# 并行执行第一阶段：有界批量投影

## 目标与范围

在保持 Volcano `init/next` 接口的基础上，让 SELECT 的投影表达式在多个
CPU 线程上计算。扫描、过滤、连接、聚合、排序以及所有写操作仍由调用线程执行。
这只是 README 中 Parallel Execution 的第一阶段，不代表所有算子都已并行化。
默认并行度为 1，保持现有行为；调用 `Database::set_parallelism(n)` 显式启用，
允许 1 到 64，非法参数返回错误且不改变配置。配置仅对该实例后续查询生效。

## 结构

1. Database 保存并行度，传入 PhysicalPlanner。写计划的整个子树强制为 1，
   避免 INSERT SELECT 的预取改变写入及错误发生顺序。
2. PhysicalProject 增加并行度和受 Mutex 保护的待输出队列、输入结束标记。
   `init` 清空旧状态并重新初始化子节点，支持嵌套循环连接中的重复扫描。
3. 并行度大于 1 时，调用线程最多预取 1024 行，拆成连续分片。
   分片数不超过配置值和输入行数；空批不创建线程，单分片直接计算。
4. 使用标准库 scoped threads，工作线程只借用输入 Tuple 和不可变表达式。
   工作线程不访问 ExecutionContext、Catalog、BufferPool 或子算子的游标。
5. 按分片顺序合并结果，因此输出顺序、重复行、NULL 以及 schema 均保持。
   不为每个输出行创建线程，不完整物化整张表；每个投影队列最多 1024 行。

## 错误与生命周期

表达式的 Result 按行保存在队列中，只有消费该行时才返回错误；预取遇到子节点
错误时，将其排在已经获取的行之后。这使上层 LIMIT 可以忽略未消费行的普通
求值错误。线程启动失败或线程 panic 转为 Execution 错误；返回前 join 所有已
启动线程。没有脱离查询生命周期的后台线程；提前 LIMIT 后待输出行随计划释放。
这一阶段会预取 LIMIT 之外的只读行，线程故障仍可能提前报告。

## 兼容性与性能限制

不增加依赖、不修改磁盘格式、不提供事务并发保证。默认串行路径继续逐行求值。
计划显示 `ParallelProject: workers=N` 便于调试。批次之间重建线程，简单表达式或
小查询可能更慢；不承诺普遍提速。后续可加入持久线程池、成本估算、并行扫描和
并行聚合，需各自先写设计、实现、测试并独立提交。

## 验证

- 保留工作区原有修改；基线 `cargo test --workspace`：41 个单测及 SQL 套件通过。
- 并行工具测试：真实多线程参与、分片顺序、空输入、单线程、线程 panic 清理。
- SQL/算子测试：1/2/4 线程等价，超过一个批次、空结果、NULL、重复值、比较表达式、
  WHERE/ORDER BY/LIMIT、聚合、连接重初始化、错误传播及错误后下一条查询。
- 整个 SQL logic test 套件在串行与并行配置下运行。
- `cargo fmt --all -- --check`、`cargo test --workspace`、`git diff --check` 全部成功后
  将设计、实现、测试、README 一起提交，并 push 当前分支。

## 实际验证结果

`cargo test --workspace` 通过：45 个库单测、2 个并行 SQL 集成测试，以及分别
在 1/4 线程下执行全部 12 个 SQL logic test 文件的回归套件。
1600 行连接结果覆盖跨批次与尾批次；Barrier 验证四个工作线程同时参与。
现有算术表达式尚未实现，本阶段使用已支持的比较表达式验证并行求值。
