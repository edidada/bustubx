# 事务持久化与崩溃恢复

## API 和日志格式

TransactionManager::new_on_disk(path) 打开一个专用事务日志文件（不是原始
Database 的页文件）。管理器持有操作系统独占文件锁，第二个进程/实例不能
同时写入。工作数据库仍是临时私有副本，未提交写永远不修改持久化文件。

每条提交记录：8 字节 magic、u64 版本、u64 payload 长度、u64 FNV-1a 校验和、
u64 头部校验和（独立验证版本和长度，防止损坏长度被当作不完整尾部）、
完整数据库页镜像、8 字节 COMMIT 标记。整数采用 little endian，校验覆盖版本、
长度与 payload，检测意外损坏而不提供防篡改能力。首次创建写 version=0。
提交先 flush 私有副本（含索引根），追加完整记录并 sync_all，成功后才替换
进程内提交版本并返回成功。禁止原地覆盖已提交记录。

## 恢复和错误

启动按顺序验证 magic、连续版本、长度、校验和、结束标记，保存最后完整镜像。
EOF 处不完整头或不完整 payload/footer 视为崩溃尾部，截断到上次完整记录位置
并 sync；完整记录校验失败或版本错误直接报 Storage，避免静默回滚已确认提交。
没有任何完整记录的非空文件报错，不自动覆盖可能损坏的数据。
append/sync 失败后管理器标记不可用，必须关闭并重新打开确定提交是否完成；
错误返回不代表一定没有提交，调用者应重新查询。成功返回的提交才有持久性承诺。

文件创建本身的目录项持久性依赖操作系统/文件系统；本版本承诺进程崩溃恢复，
不承诺所有平台新文件在突然断电时的目录持久性。日志不做压缩，空间与各提交
完整数据库大小之和有关。它是 full-image redo journal，不是 ARIES、增量 WAL
或页级 undo/redo；2PL/MVCC 的逻辑不变。

## 验证

日志单测覆盖有效记录、多个版本、每个尾部截断位置、校验损坏、版本错误以及
排他锁。真实子进程分别在已提交和未提交写后直接 exit（跳过析构），父进程
重新打开检查已提交数据保留、未提交数据不存在。集成测试覆盖 DDL/索引、
MVCC 冲突不写日志、关闭重开继续提交。全工作区测试通过后独立提交推送。
